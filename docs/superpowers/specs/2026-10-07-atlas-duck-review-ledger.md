# atlas-duck spec — review ledger

Companion to `2026-10-07-atlas-duck-design.md`. Records what each automated review round changed, which behaviour/scope decisions were applied **provisionally** (pending the user's confirmation), which decisions are still open, and what was deferred.

Reviewers: entries under "Applied — pending user confirmation" are settled for the purpose of the review loop; do not re-litigate them. Entries under "Open decisions" are intentionally not applied.

Severity scale used by the loop:
- **P0** — a core guarantee can be violated (a write executes without approval of exactly that payload; unreleased Atlassian data reaches the agent; a read or write escapes the audit log; a credential leaks) or the spec is unimplementable as written.
- **P1** — a significant gap/contradiction that would cause a real incident in normal use or force a redesign during implementation.
- **P2/P3** — everything else.

(A, recommended) rows by time range (widened for chain verification), disclosure selected separately by filter (default: current Audit filter); non-selected rows carry `payload_sha256` only, no `payload_ct`; `EXPORT {range, widened_range, selection, disclosed_count, manifest_sha256}`; `--verify-export` reports disclosed/withheld and the trust root; anchor dir defined as the out-of-band trust root. - R1 open: PAC/WPAD and NTLM/Kerberos proxies (reqwest supports neither). (A, recommended) §1.3 non-goal "PAC/WPAD evaluation and authenticated (NTLM/Negotiate/Basic) proxies; v1 supports an explicit per-instance host:port proxy or the OS static setting"; `pac_configured` and 407 → `auth_required` are already in `doctor` (§4.7, §7.2). (B) support PAC via a PAC-evaluator crate or OS proxy discovery (more scope, new dependency).
- R1 open: Batch-approval confirmation. (A, recommended; current spec text, §5.6) keep the native dialog as a Rust-generated summary of the exact set being approved, catching a UI that shows a different selection than it sends. (B) in-webview confirmation, dropping the native dialog plumbing. Either way keep the Rust-checked opened flag, per-item `candidate_rev` and duplicate exclusion; per-approval native confirmation conflicts with SC3 and is not recommended. The §2.4 containment claim is already corrected.
