    Error reference

    Errors of the command line and agents

    Every failed request of an agent carries an error object with a code, a retryable flag and a message. The code tells you what went wrong. The flag tells the agent whether sending the same request again can work. Agents should decide on status, error.code and error.retryable together, not on the exit code alone.

    Many of these errors reach you only through the agent. If you see one in the app, for example in "Recently decided (24 h)", the entry says what to do.

    usage

    The request was not valid: a command, an option or a combination of options that atlas-duck does not know. Nothing was queued. Exit 2, not retryable. Check the command with --help.

    validation

    The request was well formed but did not pass validation, for example a missing or wrong parameter of an operation. Nothing was queued. Exit 2, not retryable. Look up the operation with ops describe <op-id> and correct the parameters.

    markdown_placeholders

    The text contains placeholders that cannot be sent as written. When an agent writes a Confluence page or comment in Markdown, atlas-duck refuses a text that still contains placeholders that it put there when the agent read a page as Markdown (for example for macros or mentions). Written back, they would not mean what they stood for. Nothing was queued. Exit 2, not retryable. The agent should fetch the page again with --format storage and submit its change with body_format=storage. The storage format keeps macros and mentions as they are. Replacing the placeholders by hand, or leaving that part out, would lose them.

    op_unsupported_by_instance

    This instance does not support the operation, for example because its version is too old. Exit 2, not retryable. Use another operation or another instance, or ask the administrator of the instance.

    internal

    An internal error occurred in atlas-duck, or in the server. Not retryable: agents must not retry on their own. You can try the action again later. If it keeps happening, tell your administrator, and give them the request id and the time.

    audit_failure

    The audit log could not be written, so nothing was done. atlas-duck never acts without recording it. Exit 1. For reads and scripts the agent may try again; for writes it is not retryable, because the write has to be decided again. Check that the disk of the audit log is not full, see The audit storage is low.

    audit_storage_low

    The storage for the audit log is almost full. atlas-duck refuses new requests so that the log can always be written. Nothing was queued. Exit 1, retryable. Free disk space on the drive that holds the audit log, then try again. See The audit storage is low.

    busy

    atlas-duck limits how many connections and open requests it accepts, in total, per program and per agent session, so that no single agent can flood the queue. One of these limits is reached. Nothing was queued. Exit 11, retryable after the time that retry_after_s names. Waiting does not help when the limit on pending requests is the cause: decide or deny the pending requests first, for example with "Deny all pending from this session". Then try again.

    unreachable

    The command line could not reach the app. Except for connection_lost, nothing was queued and the exit code is 5. The details.reason says why:

    ReasonWhat to do
    not_runningThe app is not running. Start it.
    launch_timeoutThe app did not start in time, or the --timeout ran out before submission. Start the app yourself and try again.
    no_gui_sessionThere is no desktop session to start the app in. Start it in a desktop session.
    launch_blocked_by_jobOn Windows, the app could not be started from the agent's process. Start the app yourself.
    app_upgradedThe command line is newer than the running app. Restart the app.
    app_shutting_downThe app is closing. Start it again.
    store_newerThe audit data was written by a newer atlas-duck. Install that version or a newer one.
    store_unavailableThe audit store could not be opened. Restart atlas-duck. Not retryable.
    connection_lostThe connection dropped after the request was sent. The request exists, with status pending, exit 4, not retryable. Wait for it with await <id>; it may be abandoned.

    Except for store_unavailable and connection_lost, the error is retryable.

    server_identity

    The program that answered is not the app that belongs to your user. atlas-duck refuses to talk to it. Exit 5, not retryable. This is a safety check. Make sure that no other program uses the app's connection and restart atlas-duck. If it persists, tell your administrator.

    protocol_mismatch

    The command line and the app speak versions of the protocol that do not fit. Exit 5. Update both to the same version and restart the app. Restart the MCP server of the agent as well.

    upstream_http

    The Jira or Confluence server answered with an error. This code appears when a write failed after you approved it, when you released the error of a read, or when you denied a request and attached the HTTP status as a hint. Exit 6 or 3, not retryable. The details carry the HTTP status and the error messages of the instance. Read them: usually a permission, a value that the instance rejects, or a deleted object.

    upstream_network

    The connection to the instance failed. Exit 6. When it happened before the request was sent, it is retryable. When it came out of a read and you released it, it is a fixed message without data and not retryable. Check that the instance can be reached, see An instance cannot be reached.

    upstream_unavailable

    The instance is not available right now. Exit 6. Reads can be retried later. If the reason is identity_header_missing or identity_header_mismatch, a proxy in front of Jira changes the user header, so a retry does not help; ask the administrator of the instance. See Instances and tokens.

    upstream_unknown_outcome

    A write was sent, but atlas-duck does not know whether the instance carried it out, for example after a timeout, a server error or a crash. Status outcome_unknown, exit 6, not retryable. Check the target in Jira or Confluence before you do anything else. Only when the change is missing should it be requested again. The entry is under "Needs attention" with "check target", see Needs attention.

    result_too_large

    The result is too large to return. Exit 6, not retryable. The agent should ask for less: a smaller page, fewer fields, or a narrower search.

    needs_token

    A token is needed for this instance. The token is missing, or the instance has refused it. Exit 9. Add or replace the token, see Instances and tokens and A token is rejected. Agents should not retry in a loop.

    locked

    The app is locked: it cannot open its audit log or its keys. Exit 9. The details.reason says why, for example that the keychain is not available yet, that it was lost, or that the keyring lies on a network drive. Follow The app is locked.

    not_configured

    This instance, or the app, is not set up yet. Exit 9. The details.reason names the gap: the first-run wizard is not finished, no instance exists for the product, an instance uses http:// instead of https://, an instance is not confirmed, the data directory is missing or not on a local drive, or the settings file cannot be read. For the first reasons, finish the setup. If the settings file cannot be read, it may have been written by a newer atlas-duck: update atlas-duck. If the paths or the data directory are unusable, fix the directory or its permissions.

    script_syntax

    The script has a syntax error. atlas-duck compiles every script on submission and refuses a faulty one. Exit 8, not retryable. Fix the script. See Scripts.

    script_limit

    The script hit a limit and was stopped: time, memory, number of calls, data fetched or size of the result. Exit 8, not retryable. Make the script do less, or raise the limit in Settings, see Limits and confinement.

    sandbox_unavailable

    The script sandbox is not available, so scripts cannot run. Exit 8, not retryable. If the reason is app_upgraded, restart the app and try again. Otherwise the operating system does not allow the confinement, see Limits and confinement.

    result_evicted

    The outcome is known, but the result is no longer stored. Exit 10. For reads and scripts the agent can submit the request again. Do not simply repeat a write: its outcome was already decided, and it may have failed. Check the target in Jira or Confluence first.

    denied

    You denied the request. The message holds your reason. Exit 3, not retryable. The agent should resubmit only when the reason asks for a change. See Approve, release or deny.

    resolution_failed

    A name in the request could not be resolved, for example a user, a field or a project that does not exist under that name. Exit 3 when you attached it as a hint to a deny. The details name the parameter and may list candidates. The agent should fix the named parameter.

    expired

    Nobody decided the request in time. Exit 7, not retryable. Submit again only if you want that.

    cancelled

    The request was cancelled: by the agent (cancel, not retryable), because the app was quit or the system shut down (retryable). Exit 7. Nothing was executed, and a cancelled result never reaches your queue.

    In the Approvals window the same code means "The decision was cancelled": you cancelled the confirmation of a batch decision. Nothing was decided, and the requests are as they were.

    abandoned

    The request was still pending when the app crashed or was killed. Exit 7, retryable. Submit it again. A write that was already approved becomes outcome_unknown instead, see upstream_unknown_outcome.

    unknown_request

    There is no request with this id. Exit 2. Check the id, or find it with requests list.

    protocol_error

    The app and the command line tool could not agree on a message. Exit 1, not retryable. This usually means that they have different versions. Update both and restart the app.

    Errors when deciding

    These errors appear in the Approvals window when a decision cannot be applied. In every case nothing was decided, and the request is as it was. The error cancelled is described above.

    stale

    The request changed in the meantime, for example it received a new revision. Re-read the queue, open the request again and decide on what you see.

    invalid

    The decision is not allowed for this request, for example approving something that cannot be approved, or releasing with a preview that you have not opened. Open the preview first, or decide individually.

    edit_rejected

    The edit was refused, for example because it changes the target, is not valid, or is too large. The message names the reason. Correct the field, or deny the request. See Editing and redacting.

    audit

    The decision could not be recorded in the audit log, so nothing was done. Check the free space of the audit log, then try again. See The audit storage is low.

    batch_rejected

    The batch was rejected and nothing was decided. At least one request did not qualify. The reasons are listed per request, see below and Batch decisions.

    not_decidable

    The request is not waiting for a decision. Someone else decided it, it expired, or it was cancelled. Re-read the queue.

    Errors in batch decisions

    A batch lists these reasons per request. Remove the request from the batch or decide it individually.

    not_pending

    The request is no longer pending. It was decided, expired or cancelled in the meantime.

    target_param_edit

    An edit tried to change the target of the request, which is not allowed. Deny the request so that the agent asks again with the right target.

    not_opened

    The preview of the request was not opened. Open the preview of every selected request before you decide as a batch.

    not_approvable

    The request cannot be approved as it is, for example because required fields are missing, a redaction is blocked or the request cannot be rebuilt. Deciding it individually does not change that. Fix the missing fields or the blocked redaction, or deny the request.

    batch_item_flagged

    The request is flagged as a possible duplicate or as a similar request. Look at it and approve it individually.

    Errors of the server commands

    The server pages send commands to the server. These errors come back when a command fails. The error internal is described above.

    invalid_argument

    The request contains an invalid value. Check what you entered and try again.

    not_found

    The request, or the thing that it names, does not exist any more. Reload the page.

    release_blocked

    This request cannot be released. The redactions that you made, or the data itself, would let through something that should have been held back, or the result could not be built exactly. The page names the reason. Deny the request, or drop the flagged items. See "When a release is blocked" in Editing and redacting.

    unknown_command

    The server does not know this command. The page and the server are of different versions. Reload the page; if it persists, tell your administrator.

    not_ready

    Your store is not ready yet, for example right after a restart. Try again in a moment.

    audit_unreadable

    An audit entry could not be read, which can mean that it is damaged. Tell your administrator the first time it happens, and ask them to verify the audit log, see Verify the chain.

    audit_failed

    The audit log could not be read. Try again later. If it persists, tell your administrator.

    Errors of the server API

    The server answers errors with an HTTP status and a code. The web pages translate the code into a message. The code is useful when you talk to your administrator.

    auth/invalid_credentials

    HTTP 401. The username or password is wrong. Sign in again with your directory account.

    auth/empty_password

    HTTP 400. You did not enter a password.

    auth/directory_unavailable

    HTTP 503. The server cannot reach the directory that checks your password. People who are signed in can keep working. Try again later, or tell your administrator.

    auth/not_permitted

    HTTP 403. This account may not use atlas-duck: it belongs to none of the groups that the server admits, or it was deactivated. Ask your administrator, see Users and roles.

    auth/no_session

    HTTP 401. You are not signed in. Sign in first.

    auth/session_expired

    HTTP 401. The session expired. Sign in again.

    auth/csrf_mismatch

    HTTP 403. The request token does not match your session, for example because the page was open for a long time or in two sessions. Reload the page.

    auth/origin_mismatch

    HTTP 403. The request comes from another origin than the server's own address. Use the address that your administrator gave you, and do not call the server from another website.

    auth/role_required

    HTTP 403. The page or action needs a role that your account does not have, such as admin or auditor. See Users and roles.

    auth/bearer_not_accepted

    HTTP 403. API keys and OAuth tokens cannot be used here. Only the MCP endpoint accepts them; decisions can only be made by a person who is signed in. See The MCP endpoint.

    auth/api_key_invalid

    HTTP 401. The API key or token is not valid: it is mistyped, revoked or expired, or its user was deactivated. Create a new key, see API keys.

    auth/scope_missing

    HTTP 403. The key lacks the scope that this needs. Create a key with the scope, see Scopes.

    api/bad_request

    HTTP 400. The request is malformed. If you use the web pages, reload them. If an own program sends it, check the body.

    api/not_found

    HTTP 404. Not found. The address or the object does not exist.

    api/unknown_command

    HTTP 404. The server does not know this command. Reload the page; the page and the server may be of different versions.

    api/body_too_large

    HTTP 413. The request body is too large. Send less data.

    api/too_many_streams

    HTTP 429. You have too many pages open that wait for live updates. Close some tabs.

    instance/invalid

    HTTP 400. The instance is not valid. Check the alias (letters, digits, - and _), the product, an https:// base URL and the proxy, and that the product has only one default. See Manage instances.

    instance/exists

    HTTP 409. An instance with this alias exists already. Choose another alias.

    instance/unknown

    HTTP 404. No instance has this alias, perhaps because an administrator removed it. Reload the page.

    pat/check_failed

    HTTP 422. The instance refused the token. Check that you copied it completely and that it has not expired or been revoked. See A token is rejected.

    pat/instance_unreachable

    HTTP 502. The server cannot reach the instance to check the token. Try again later, or ask your administrator. See An instance cannot be reached.

    api_key/limit_reached

    HTTP 409. You have the maximum of 25 active keys. Revoke one first, see API keys.

    api_key/expiry_out_of_range

    HTTP 400. The expiry must be a whole number of days from 1 to 90.

    api_key/name_invalid

    HTTP 400. The name must be 1 to 64 characters long and contain no control characters.

    api_key/scope_invalid

    HTTP 400. Choose at least one scope, and only known ones.

    store/unavailable

    HTTP 503. The store is not available. Try again in a moment. If it persists, tell your administrator.

    oauth/disabled

    HTTP 404. OAuth is not enabled on this server. Use an API key instead, see API keys.

    oauth/request_unknown

    HTTP 404. This authorization request is unknown. It may have been answered already, or it belongs to another session. Start again from the app, see Authorising an app.

    oauth/request_expired

    HTTP 410. This authorization request expired. Start again from the app.

    oauth/grant_unknown

    HTTP 404. There is no such connected app. It may be revoked already. Reload "Connected apps".

    audit/user_unknown

    HTTP 404. No such user has an audit log. Go back to the list of users.

    audit/read_not_recorded

    HTTP 503. The read could not be recorded, so nothing was read. Auditing is itself audited, and the server refuses to show data that it cannot record. Try again later. See The auditor role.

    audit/export_busy

    HTTP 409. An export of this log is already running, or the server runs its maximum number of exports. Try again when it has finished.

    audit/export_unknown

    HTTP 404. There is no such export, or it belongs to someone else.

    audit/export_expired

    HTTP 410. The export is no longer available: it expired or was already downloaded. Start a new one, see Export the log.

    audit/export_failed

    HTTP 500. The export failed. Start a new one. If it keeps failing, tell your administrator.

    server/maintenance

    HTTP 503. The server is in maintenance, for example for a restore. Try again later. See Maintenance.

    auth/rate_limited

    HTTP 429. Too many failed sign-ins. Wait for the time that the Retry-After header names, then try again.
